## テーマ

「AIエージェントが作った成果物を、誰が・何を根拠に・いつ採用するか」— エージェント出力の**検収生態系**。前提書の3層モデル(エージェント作業 / 採用境界 / バックオフィス)の真ん中の層を対象領域とする。

## 思考ツールの問い(モデリング前)

- **未来の変化因子**: エージェント実行量の爆発(報告を人が読む方式の破綻) / EU AI Act等の「AIがやった作業」の監査要求 / sandbox提供者の「検証可能性」競争 / モデルの自己申告が器用になるほど嘘も器用になる
- **先見倍歴**: コード生成の速度は30年で人力→補完→自律実行へ。速度が2倍になると「人が読む検収」は完全にボトルネック化し、検証の機械化・外部委託が必然になる
- **制約なき発想**: コスト・組織・慣習がなければ「全実行を第三者機関が再実行して照合する」世界が自然(金融取引の清算機関と同型)
- **異質の取り入れ**: 金融(信用調査・清算・保険)、物流(荷主の申告 vs 運送会社の追跡記録)、医療(ダブルチェック・監査証跡)、バグバウンティ(発見に報酬)
- **別のゲーム(M10)**: この領域の前提を否定したゲーム — 「検証は人間がやる」「証拠は実行者が作る」「採用されたものだけが価値」「検証は一度だけ」「信用は製品(ブランド)に付く」の5つを後述のバイアス表で否定する
- **Z軸探索**: 競合が競う軸(X=精度/検出率、Y=速度/低コスト)の外にある第3軸 = **「その記録を誰が発行したか」(証拠の発行者)**。実行基盤が発行する記録への依拠は、精度でも速度でもない別次元の競争条件
- **堀(schlep)**: 誰もやりたがらない面倒 = プロバイダ固有の記録形式の吸収 / 「正解が分かっているバグ入りタスク群(撒き種コーパス)」の手作り / 再実行ハーネスの泥臭い整備。引き受ければ後発が真似しにくい堀になる
- **墓場(tarpit)**: receipt系先行9件が伸びなかった死因 = 「もう1枚の信じるべき自己申告」だった(証拠を作る者と証拠を信じる者が同一)。自案が当てはまらない根拠 = プロバイダ発行アンカー(非自己申告)+関所品質の計量(性能を数値で示す)の2点 — ただし**計量が実測で崩れたら同じ墓場に入る**危険は残る

## 生態系モデルと根源的バイアス

### 生態系の構造

- **アクター**: エージェント製品(Devin/Claude Code/Codex/Cursor等) / 実行基盤(sandbox提供者 = ConTree・E2B等。「監視カメラの持ち主」) / レビュー層(PRレビューツール・CI) / 採用者(開発者・チーム) / 規格・署名系(in-toto/SLSA) / ベンチマーク系 / 将来の監査・規制
- **フロー**: 指示 → 実行 → **自己申告** → 人のレビュー → 採用/却下。「採用してよいという信用」を生産しているのは**人の注意だけ**で、それ以外の誰も信用を作っていない
- **見えない力学**: ①検証コストはレビュアーの時間で支払われ誰も請求しない ②失敗・却下の情報は採用時点で捨てられる ③実行基盤は正確な実行記録を持っているのに、それは運用者向けのログであって検証者向けの証拠として価値化されていない ④競争軸が「速く・賢く書く」側だけにあり「検証可能であること」は誰の売りにもなっていない

## 選定した破壊レバー

| # | レバー | 戦略的意義 | 連鎖的変化の見通し |
|---|---|---|---|
| L1 | 証拠の発行者を当事者→第三者(実行基盤)に差し替える | B2の直接破壊。情報非対称を潰す | 「読んで信じる」→「照合して確かめる」に変わり検証が機械化・安価化 |
| L2 | 却下・失敗の記録を資産化する | B4破壊。価値フロー再設計 | 失敗の蓄積が検出器・コーパスを強くする→後発が追えない堀 |
| L3 | 信用の単位を製品→個別runへ粒度破壊 | B6破壊 | モデル/エージェント間で「報告の生存率」が比較可能になる→計量市場 |
| L4 | 検証の時間軸を破壊(採用後でも遡って再検証できる) | B5破壊 | 監査・遡及検証が可能になり「採用=終わり」が消える |

## 堀と墓場

- **皆が避けている面倒(=堀候補)**: プロバイダ記録形式の吸収・撒き種コーパスの手作り・再実行ハーネスの整備 — 全部引き受ける設計済み。「正解が分かっている悪い仕事の標本集」は作るのが面倒で誰も持っていない資産
- **沈んだ先例の死因**: receipt系9件=「もう1枚の自己申告」に留まった / PRレビューツール=精度競争の軸で頭打ち。**自案に当てはまらない根拠**: 外部アンカー(L1)+却下資産化(L2)+計量(L3)。当てはまるリスク: 計量値が実測で平凡(検出率が当たり前)なら「新しい発見がないツール」に転落する

## コンセプト群(6つ)

### コンセプト1: runanchor関所(現行案)
- 破壊の核心: B2をL1で破壊 + B4をL2で破壊
- 内容: 各runにプロバイダ発行IDつき検収書・再実行照合・append-only台帳・人/機械の採用関所
- 新たな生態系・価値: 「読む検証」から「照合する検証」への移行の最初の道具
- 課題・新トレードオフ: 単体ツール止まりだと「receipt系10個目」に見える危険。計量・台帳の活用が価値の芯

### コンセプト2: エージェント信用調査局(クレジットビューロー)
- 破壊の核心: B6をL3で破壊 — 信用を製品ではなくrun単位に分解し、モデル別の「報告生存率(検証を生き残った率)」を集計
- 内容: 検収書を集める公開台帳+リーダーボード。「Devin製のrunは検証通過率◯%」という比較軸を作る
- 新たな生態系・価値: 実行基盤・エージェント・採用者の間に「信用情報」の流通層が生まれる
- 課題: ネットワーク効果なしでは動かない・悪意ある提出の耐性・「採点される側」の反発

### コンセプト3: 検証バウンティ(嘘発見の市場)
- 破壊の核心: B1を破壊 — 検証を人の職務ではなく報酬つきの市場活動にする
- 内容: 却下候補のrunに賞金を懸け、第三者が再実行して嘘を発見したら報酬。不正率に賭ける予測市場の変種
- 課題: ハッカソンには重すぎる・流動性の前提・インセンティブ設計が難しい。**構想バックログ行き**

### コンセプト4: 却下鉱山(失敗データで鍛える検出器)
- 破壊の核心: B4をL2で破壊 — 却下receiptの蓄積自体が「嘘の見抜き方」を鍛える教材になる
- 内容: 関所の副産物=却下パターン集を、機械レビュアーの訓練/評価データにする。撒き種コーパスと二重構造
- 課題: データが貯まるまで価値が先送り。初速では関所自体の価値が先

### コンセプト5: 検査保険(保証つき採用)
- 破壊の核心: B5をL4で破壊 — 採用を一回の行事ではなく継続的な責任(保証付き)にする
- 内容: run採用時に「あとで再検証に落ちたら違約」という担保を付ける設計。信頼の価格化
- 課題: 規制・契約の要素が大きく個人ハッカソンの射程外。**構想バックログ行き**

### コンセプト6: 監査証拠基盤(AI作業のSOC2)
- 破壊の核心: 未来の変化因子(監査要求)を先取り — B5/L4と組み合わせ、receipt台帳を「AIがやった作業の監査証跡」として組織のコンプライアンスに供給
- 内容: 組織内の全エージェント実行の検証済み台帳+監査向け抽出レポート
- 課題: 規制需要はまだ仮説。ただし「台帳を公共財として残す」向きは現行設計と両立する

## 総括: 戦略的示唆

現行案(C1)はレバーL1(証拠発行者の差し替え)とL2(失敗資産化)を既に体現しており、構造破壊的には**方向は正しい**。ただし二つの強化余地が浮き出た:

1. **「計量」を機能ではなく製品の芯に据える**(L3/finding-as-product): 「検出率◯%・特異度◯%を実測した唯一の関所」という顔を前に出すと、receipt系9件との差が「設計の差」ではなく「実証された差」になる。計量値がそのまま出荷物 — 現行のeval計画はこの線に乗っているので、提出物の顔として最前面に出すべき
2. **台帳を「公共財」として語る**(L4/C6): run単位・append-onlyの台帳は設計済みだが、説明文で「将来の監査・遡及検証に耐える記録」と位置づけると、単なる開発ツールから「エージェント時代の基盤部品」へ格が上がる(追加実装なしで言い方だけ変える)

逆方向の警告: C2/C3/C5は射程外だが、「関所が新しい権力になる」問題(関所の嘘を誰が検証するか)は提出物のFAQに答えを書いておくと審査員の突っ込みを先回りできる。

### 生態系モデルの訂正

- **「誰の売りにもなっていない」の過剰主張を訂正**: 検証可能性を売る先行はある(Pipelock等9件・premises追補2)。正確には「勝てる軸として確立していない」
- **L1の成立条件を明記**: 第三者アンカーは**エージェント層と実行基盤層が分離している場合のみ**効く。垂直統合型(実行環境を自社内包するエージェント)ではプロバイダ記録が提供者自身の記録に退化 — runanchorの射程は分離型スタックに限る(ハッカソン構成Nemotron→ConTreeは分離型なので成立)
- **アクター追加**: 機械判定主体(LLM-as-judge・AIレビュアー層 — CodeRabbit等は「人の注意」独占を部分的に崩している)、モデル提供者(嘘の生成と判定の両側を供給)、敵対アクター(ログ偽装者)
- **価値フローの欠落を補完**: 再実行照合はcomputeを食う — 「検証が安価化」は「誰が払うか」への移転設計(L6)があって初めて言える

### 墓場対処の追加(倍賭けの解消)

**負の発見への退路**(finding-as-product): 検出率が平凡・負に出た場合でも、「既存の素通しレビューでは撒き種バグの◯%が関所なしで通り抜ける」「静的な自己申告だけでは検出不能な嘘の型」という**負の実測自体を発見として出す**設計。計量値が美しくなくても計量の存在と手順公開が価値になる。ただしこれはL5(第三者再現可能性)が前提 — 再現できない負の発見は誰も信じない。

### コンセプト群の整理

- **C4・C6は「何を作るか」の非連続ではなく変奏と明示**: C4=C1の副産物(どう活かすか)、C6=同じものの売り先変更(どう売るか)。非連続な新軌跡はC2・C3・C5の3件
- **C3〜C6の「新たな生態系・価値」を補完**:
  - C3(検証バウンティ): 嘘発見が報酬市場になる — 検証が「職務」から「市場活動」へ
  - C4(却下鉱山): 却下データが検出器の訓練資産化 — 「失敗は捨てる」の破壊が直接の収益源に
  - C5(検査保険): 採用が保証つき継続責任化 — 信頼が価格化され保険市場が生まれる
  - C6(監査基盤): AI作業の監査証跡が公共財化 — 規制需要が来た時点で先に占有できる

### アンカーの限界(墓場節の根拠へ明記)
